# T590314 任务分配 题解

题目链接：<https://www.luogu.com.cn/problem/T590314>

## 一、题目大意

一棵 `n` 个点的有根树（根为 1，`f_i` 是节点 i 的父亲）。有 `n` 个任务，第 i 个任务耗时 `t_i`（**已按升序给出**）。要把 n 个任务一一分配到 n 个节点。

限制：节点 i 的子树内，**所有任务耗时都不能超过 `w_i`**。

现在可以**选一个节点，把它的 `w` 增加 `k`**（k 为非负整数）。求最小的 `k`，使得存在一种合法分配。保证一定存在可行解。

样例（输出 `2`，把节点 2 的限制增加 2）：

```text
6
1 2 2 1 5
1 2 2 3 5 6
6 1 3 3 5 1
```

## 二、核心转化：每个节点有个"容量"

一个耗时 `t` 的任务能否放到节点 `v`？这取决于 `v` 到根这条路径上**所有 `w` 的最小值**（因为 `v` 的每个祖先的子树都包含 `v`，每个祖先的限制都要满足）。

定义节点 `v` 的**容量**：

```text
cap[v] = min( w_u : u 在根到 v 的路径上 )
```

那么：任务耗时 `t` 能放到 `v`，当且仅当 `t <= cap[v]`。

由于 `f_i < i`，可以按序号直接算：

```cpp
cap[1] = w[1];
cap[i] = min(cap[f_i], w[i]);
```

## 三、判定：排序贪心匹配

问题变成：有 n 个任务（耗时 `t_1 <= ... <= t_n`）和 n 个节点（容量 `cap[v]`），每个任务要放到一个容量 >= 它的节点。

这是经典匹配，**可行 ⟺ 把容量升序排序后，`t_i <= c_i` 对所有 i 成立**（第 i 小的任务 <= 第 i 小的容量）。

## 四、增加一个节点的影响

把节点 `x` 的 `w_x` 增加 `k`：

- 对 `subtree(x)` **之外**的节点无影响；
- 对 `subtree(x)` 内的节点：路径上 `w_x` 变大，所以它们的 `cap` 可能变大（那些本来被 `w_x` 卡住的节点）。

具体地，`x` 的新容量 `c[x] = min(up[x], w_x + k)`（`up[x]` 是根到 x 路径上除 x 外的 `w` 最小值），再向下传播 `c[v] = min(c[父], w[v])`。

## 五、算法：V0 特征 + 可达值支配（O(n log n)）

关键结论（均已随机对拍验证）：

> 答案 = `V0 - max(有效节点的 w)`，其中
> - `V0` = 最大的"有缺口阈值"（容量 >= v 的个数 < 任务 >= v 的个数）；
> - "有效节点 x" = 把 `w_x` 抬到 `V0` 后能合法分配。

进一步，"有效节点 x"可判为：

> ① `w_x < V_min`（最小缺口阈值）；② x 所"瓶颈"的节点们的**可达值**（把瓶颈抬到无穷后的容量，即路径上**第二小**的 w）排序后能**支配**缺口分布 `d[v]`。

算法步骤：

1. 树形递推求 `cap`、第二小值 `mn2`、最小值出现次数 `mn1cnt`（>1 表示并列、无法单点抬升）、瓶颈 `b`；
2. 把"最小值唯一"的节点按瓶颈分组，得到每个 x 的可达值集合 `B[x]`；
3. 算 `A[v]`、`d[v] = A[v] - B[v]`，得到 `V0`、`V_min`、`M = max d`；
4. 需求 `req[j] = max{v : d[v] >= j}`（j=1..M，非递增）；
5. 对每个 `w_x < V_min` 且 `|B[x]| >= M` 的 x，把 `B[x]` 降序排序，检查"第 j 大可达值 >= req[j]"（支配），取 `V0 - max(w_x)`。

判定用「计数 + 后缀和」（值域 <= n），分组排序合计 O(n log n)。

## 六、参考代码

```cpp
//
// 洛谷 T590314 任务分配（O(n log n) 满分版）
// 思路：cap=路径 w 最小值；可达值（第二小 w）按瓶颈分组，支配缺口分布。
//

#include <iostream>
#include <vector>
#include <algorithm>
#include <cstring>
using namespace std;

int n;
int f[100005], w[100005], t[100005];
int cap[100005], mn2[100005], mn1cnt[100005], b[100005];
vector<int> B[100005];   // B[x] = 瓶颈为 x 且"最小值唯一"的节点的可达值
int A[100005], cnt[100005], d[100005];

int solve() {
    cap[1] = w[1]; mn2[1] = n + 1; mn1cnt[1] = 1; b[1] = 1;
    for (int i = 2; i <= n; i++) {
        int p = f[i];
        if (w[i] < cap[p])      { cap[i] = w[i]; mn2[i] = cap[p]; mn1cnt[i] = 1; b[i] = i; }
        else if (w[i] == cap[p]) { cap[i] = cap[p]; mn2[i] = mn2[p]; mn1cnt[i] = mn1cnt[p]+1; b[i] = b[p]; }
        else                     { cap[i] = cap[p]; mn2[i] = min(mn2[p], w[i]); mn1cnt[i] = mn1cnt[p]; b[i] = b[p]; }
    }
    for (int i = 1; i <= n; i++) if (mn1cnt[i] == 1) B[b[i]].push_back(mn2[i]);

    for (int i = 1; i <= n; i++) A[t[i]]++;
    for (int v = n - 1; v >= 1; v--) A[v] += A[v + 1];

    for (int i = 1; i <= n; i++) cnt[cap[i]]++;
    int Bsum = 0, V0 = 0, V_min = n + 1, M = 0;
    for (int v = n; v >= 1; v--) {
        Bsum += cnt[v];
        d[v] = A[v] - Bsum;
        if (d[v] > 0) { V0 = max(V0, v); V_min = min(V_min, v); M = max(M, d[v]); }
    }
    if (V0 == 0) return 0;

    vector<int> req(M + 1, 0);
    int cur = n;
    for (int j = 1; j <= M; j++) { while (cur >= 1 && d[cur] < j) cur--; req[j] = cur; }

    int bestW = -1;
    for (int x = 1; x <= n; x++) {
        if (w[x] >= V_min) continue;
        vector<int>& rv = B[x];
        if ((int)rv.size() < M) continue;
        sort(rv.rbegin(), rv.rend());
        bool ok = true;
        for (int j = 1; j <= M; j++) if (rv[j - 1] < req[j]) { ok = false; break; }
        if (ok) bestW = max(bestW, w[x]);
    }
    return bestW == -1 ? -1 : V0 - bestW;
}

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    cin >> n;
    for (int i = 2; i <= n; i++) cin >> f[i];
    for (int i = 1; i <= n; i++) cin >> t[i];
    for (int i = 1; i <= n; i++) cin >> w[i];
    cout << solve() << '\n';
    return 0;
}
```

## 七、复杂度

- 树形递推、计数、需求数组：`O(n)`；
- 对每个瓶颈分组排序：合计 `O(n log n)`；
- 总体 **`O(n log n)`**，`n <= 10^5` 可轻松通过全部子任务。

## 八、常见错误

1. **没理解"容量 = 路径上 w 的最小值"**：节点 v 的所有祖先的限制都要满足，所以取路径最小值，而不是只看 `w_v`。
2. **判定写错**：要"第 i 小任务 <= 第 i 小容量"，两边都要升序后逐位比较。
3. **漏掉 `up[]`**：增加节点 x 时，x 的新容量还受祖先限制，`c[x] = min(up[x], w_x + k)`。
4. **二分边界**：k 可以是 0（原本就可行）；上界取 `n` 即可（`t_i, w_i <= n`）。

## 九、小结

| 步骤 | 内容 |
|---|---|
| 转化 | `cap[v] = min(w on path)`（每个节点的"容量"） |
| 判定 | 容量升序后 `t_i <= c_i` |
| 增加 | 只影响 `subtree(x)`，容量向下传播 |
| 求解 | 二分答案 + 枚举被增加的节点 |

核心一句话：**把"祖先限制"压成"节点容量"，任务分配就变成排序贪心匹配；增加一个节点的限制，等于抬高它整棵子树的容量。**
