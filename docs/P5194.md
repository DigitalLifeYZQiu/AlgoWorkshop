# P5194 [USACO05DEC] Scales S 天平 题解

题目链接：<https://www.luogu.com.cn/problem/P5194>

## 一、题目大意

约翰有一架天平，配了 `N` 个砝码，每个砝码的质量都是正整数，且满足两个条件：

1. 质量按**非递减**（升序）给出；
2. 从**第三个**砝码开始，每个砝码的质量 ≥ **前两个砝码质量之和**。

给定一个上限 `C`，要求从这些砝码中选出**若干个**，使它们的总质量**不超过 C 且尽可能大**，输出这个最大总质量。

输入格式：

- 第一行两个整数 `N` 和 `C`；
- 接下来 `N` 行，每行一个砝码的质量（已按升序给出）。

输出格式：一个整数，表示不超过 `C` 的最大总质量。

数据范围：`N <= 1000`，`C <= 2^30`，砝码质量均为正整数。

样例输入：

```text
3 15
1
10
20
```

样例输出：

```text
11
```

样例解释：砝码 `20` 本身已超过 `C`，不能用；选 `1` 和 `10`，总和 `11` 是 `<= 15` 的最大值。

## 二、解题思路

### 1. 关键性质：有效砝码只有约 46 个

条件 2 让砝码质量呈**斐波那契式增长**：最慢的情况是前两个都为 `1`，即

```text
1, 1, 2, 3, 5, 8, 13, ...
```

恰好是斐波那契数列，呈指数级增长。而斐波那契数 `F(47) ≈ 2.97 * 10^9 > 2^30`，因此：

> 质量 `<= C` 的砝码最多只有约 46 个。

所有质量 `> C` 的砝码单个就超重了，**永远不可能被选**，直接丢弃。于是问题规模从 `N <= 1000` 骤降到 `m <= 46`，让「枚举子集 + 剪枝」成为可能。

### 2. DFS + 前缀和剪枝

把过滤后的砝码按升序排好，**从大到小**依次决定「选 / 不选」。定义前缀和：

```text
pre[i] = w[0] + w[1] + ... + w[i]
```

DFS 状态 `(idx, cur)` 表示：当前已选总质量为 `cur`，正在考虑下标 `idx` 的砝码（剩余可选范围是 `0..idx`）。

核心剪枝：如果

```text
cur + pre[idx] <= ans
```

那么即使把剩下所有砝码全选上，也超不过当前最优 `ans`，**直接返回**，不再往下搜。

**剪枝的正确性**：它只跳过「最优上界 `<= ans`」的子树，绝不可能错过比 `ans` 更优的解。

### 3. 为什么优先"选"大砝码

递归时先尝试「选当前砝码」、再尝试「不选」：

```cpp
if (cur + w[idx] <= C)
    dfs(idx - 1, cur + w[idx]);   // 先"选"
dfs(idx - 1, cur);                // 再"不选"
```

这样能更快找到一个接近 `C` 的 `ans`，让前缀和剪枝尽早生效，显著减少搜索量（只影响效率，不影响正确性）。

## 三、参考代码

```cpp
//
// 洛谷 P5194 [USACO05DEC] Scales S 天平
// 思路：丢弃 > C 的砝码 -> 前缀和 + DFS 剪枝枚举子集。
//

#include <iostream>
#include <vector>
#include <numeric>
#include <algorithm>

using namespace std;

int n;
long long C, ans;
vector<long long> w;     // 过滤后（质量 <= C）的砝码，保持升序
vector<long long> pre;   // pre[i] = w[0..i] 的前缀和

// 考虑下标 idx 的砝码（从大到小），当前已选总质量为 cur
void dfs(int idx, long long cur)
{
    ans = max(ans, cur);                 // 每个状态都可能是答案
    if (idx < 0) return;                 // 所有砝码都已考虑完

    // 前缀和剪枝：剩余所有砝码全选也超不过当前最优，直接返回
    if (cur + pre[idx] <= ans) return;

    // 优先"选"当前砝码（更快得到接近 C 的答案，增强剪枝效果）
    if (cur + w[idx] <= C)
        dfs(idx - 1, cur + w[idx]);
    // "不选"当前砝码
    dfs(idx - 1, cur);
}

int main()
{
    cin >> n >> C;

    // ---------- 读入并过滤：质量 > C 的砝码永远用不上 ----------
    w.reserve(n);                        // 预留容量，避免反复扩容
    for (int i = 0; i < n; i++)
    {
        long long x;
        cin >> x;
        if (x <= C) w.push_back(x);      // 只保留 <= C 的砝码
    }

    // ---------- 计算前缀和 ----------
    int m = w.size();
    pre.resize(m);
    partial_sum(w.begin(), w.end(), pre.begin());  // pre[i] = w[0] + ... + w[i]

    // ---------- DFS：从最大的砝码开始考虑 ----------
    dfs(m - 1, 0);

    cout << ans << endl;
    return 0;
}
```

## 四、复杂度分析

- **预处理**（过滤 + 前缀和）：`O(N)`；
- **DFS**：最坏情况下是 `O(2^m)`，但 `m <= 46`，且「前缀和剪枝 + 优先选大砝码」会砍掉大量分支，实际运行非常快，洛谷上稳定通过；
- **空间**：`O(m)`，几乎无额外开销。

> 备选方案：折半搜索（meet in the middle）。把 `<= 46` 个砝码分成两半，各枚举 `2^23` 个子集和，排序后二分配对，复杂度 `O(2^(m/2) * log)`，是理论上确定有界的做法，但代码更复杂、内存更大。

## 五、常见错误

1. **忘记过滤 `> C` 的砝码**：它们会增大 `m`，影响前缀和的正确含义，甚至导致搜索范围错误。

2. **剪枝条件写反或写成 `<`**：正确是 `cur + pre[idx] <= ans` 才剪枝（等于时也无法得到更优解）。

3. **递归顺序不讲究**：先"不选"再"选"会导致 `ans` 迟迟达不到较大值，剪枝效果变差，可能超时。

4. **漏掉更新 `ans` 的时机**：必须在**进入 dfs 时**就 `ans = max(ans, cur)`，否则某些「只选部分砝码」的状态不会被记录。

5. **用 `int` 存质量和**：`C <= 2^30`，前缀和可能超过 `int` 范围，要用 `long long`。
